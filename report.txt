1. Incremental sync has a correctness bug — dirty leaf replacement orphans parent children
In sync_node_incremental, when a dirty leaf is replaced, a new taffy::NodeId is created and inserted into node_map, but the parent's child list in Taffy is never updated to reference the new node. The parent only gets updated if it is itself dirty or its children list changed — but child_taffy_nodes for the parent was collected before this replacement happened, meaning the stale taffy::NodeId is used.
rust// The replacement gets a new taffy id...
let replacement = self.taffy.new_leaf_with_context(style, ctx)...;
self.node_map.insert(node.id, replacement);
// ...but the parent's set_children call will use the OLD id
// because sync_taffy_children already returned before this ran.
Fix: return the taffy::NodeId from sync_node_incremental (which you already do) and ensure the parent always calls set_children when any child id changed — not just when the child list changed structurally. You already track children_changed by comparing slices, but because the replacement happens inside the recursive call, the returned id is the new one, so child_taffy_nodes will contain it. Double-check that sync_taffy_children collects return values from the recursive sync_node_incremental calls — it does — so this is actually fine as long as the parent comparison fires correctly. The real risk is that children_changed compares against self.child_map, which stores the previous ids, so a replaced leaf will correctly trigger children_changed = true. This is safe but fragile; a comment explaining this invariant would help.

2. expand_dirty_with_ancestors is computed but its result is unused for the actual sync
rustlet propagated_dirty_nodes = expand_dirty_with_ancestors(tree, dirty_nodes);
self.dirty_layout_nodes = sync_dirty_nodes.clone(); // ← only used for debug
self.sync_incremental_tree(..., &sync_dirty_nodes); // ← uses the non-expanded set
The ancestor expansion is only used to populate result.debug.dirty_layout_node_count. The sync itself only marks direct dirty nodes. This is intentional if Taffy propagates dirtiness upward internally, but it's not documented. If Taffy does not do this automatically, then layout containers above a changed leaf won't be recomputed.
Fix: Add a comment making this contract explicit, or verify whether set_style/set_children on a child marks the parent dirty in Taffy automatically. If it does, document it. If it doesn't, pass propagated_dirty_nodes into the sync.

3. taffy_style_for_node and compute_taffy_style_for_node are confusingly split
taffy_style_for_node handles the node's own style and some root/overlay special cases. compute_taffy_style_for_node adds parent-context-aware mutations (scroll shrink, stack grid placement). The naming doesn't make the relationship obvious, and taffy_style_for_node is not pub but does a lot of root-specific work that conceptually belongs with the parent-aware pass.
Suggested rename and restructuring:
rustfn base_taffy_style(node, viewport, theme) -> taffy::Style { ... }       // pure node style
fn contextual_taffy_style(tree, node, viewport, theme) -> taffy::Style { // adds parent context
    let mut style = base_taffy_style(node, viewport, theme);
    // scroll shrink, stack grid placement, etc.
    style
}

4. label_text_for_node fallback silently uses child text nodes
The comment says "Fallback is only for intrinsic sizing of legacy builder patterns", but this fallback fires for every widget that doesn't have an explicit label — including new code. If a button's label child text is used for sizing, it will be correct, but if the widget has non-label child text (e.g. a description paragraph inside a card widget), it will silently size using the wrong text.
Fix: Scope the fallback more tightly or remove it and require explicit labels. At minimum, only apply it to WidgetKinds where child-text-as-label is a known pattern:
rust// Only fall back for widget kinds that historically used child text as label
if matches!(widget_kind, WidgetKind::Button | WidgetKind::Checkbox | ...) {
    node.children.iter()...find_map(...)
}

5. max_length_percentage uses a fragile percent-detection heuristic
rustlet current_is_percent = current_auto
    .resolve_to_option(100.0, |_, _| 0.0)
    .zip(current_auto.resolve_to_option(200.0, |_, _| 0.0))
    .is_some_and(|(a, b)| (a - b).abs() > f32::EPSILON);
This detects percentages by checking if the value changes when the parent size changes — a clever but brittle approach. If Taffy ever changes how resolve_to_option handles edge cases, this silently breaks. It also returns early without enforcing the minimum for percentages, which may or may not be correct.
Fix: Match on the internal representation directly, or restructure max_length_percentage to accept the original Length value before it's been converted to taffy::LengthPercentage, where the variant is explicit:
rustfn ensure_min_padding(length: Option<&Length>, minimum: f32) -> taffy::LengthPercentage {
    match length {
        Some(Length::Percent(_)) => to_taffy_length_pct(length), // don't clamp percents
        Some(Length::Px(px)) => taffy::LengthPercentage::length(px.max(minimum)),
        _ => taffy::LengthPercentage::length(minimum),
    }
}

7. Fixed position is silently treated as Absolute with a warning, but the warning is emitted per-node every frame

If any fixed-position node exists, this pushes a new warning string every time layout runs. Callers accumulating warnings over time will see them grow unboundedly.

8. clips_overflow_node and overflow mapping in to_taffy_style are duplicated logic
Both functions map Overflow variants. If a new overflow variant is added, it needs to be updated in two places with no compile-time enforcement.
Fix: Extract a shared helper:
rustfn to_taffy_overflow(overflow: Option<crate::core::Overflow>) -> (taffy::Overflow, bool /*clips*/) {
    match overflow {
        Some(Overflow::Hidden | Overflow::Clip) => (taffy::Overflow::Hidden, true),
        Some(Overflow::Scroll | Overflow::Auto) => (taffy::Overflow::Scroll, true),
        _ => (taffy::Overflow::Visible, false),
    }
}
