# 04-01: WindowId newtype + dispatch_to_window + AppEvent + example migration

**Phase:** 4 (Multi-Window)
**Plan:** 1 of 3
**Date:** 2026-06-04
**Source context:** `.planning/phases/04-multi-window/04-CONTEXT.md`
**Decisions covered:** D-01 (WindowId newtype), D-02 (UiRuntime.window_id invariant), D-04 (5 example migrations), D-10 (dispatch_to_window), D-11 (no window_id on UiEvent), D-12 (AppEvent + dispatch_app_event), D-19 (static assert UiRuntime: Send + Sync — also relies on D-17 from 04-02; the static assert is added here but only fully checks once 04-02's `Send + Sync` bounds land)

<objective>

Give every `UiRuntime` a window identity and give the host a routing seam. After this plan, the lib has a first-class `WindowId` newtype, a `UiRuntime::for_window(id, &ctx)` constructor, a `dispatch_to_window` method the winit host loop calls per-window, an `AppEvent` enum for cross-window events, a static `Send + Sync` assert on `UiRuntime`, and the five winit examples migrated off the "ignore `_id: WindowId`" pattern.

The surface of this plan is the **per-window seam** (D-01, D-02, D-04, D-10, D-11, D-12, D-19) and the **migration**. The cross-cutting `ProcessContext` / `NodeIdAllocator` / `SharedAccessibility` types and the `Send + Sync` trait bounds live in plan 04-02. The renderer / shared atlas / multi-window example / tests live in plan 04-03.

</objective>

<context>

Phase 4 context (D-01..D-19) is in `.planning/phases/04-multi-window/04-CONTEXT.md`. The current `UiRuntime` is single-window: `src/runtime/runtime.rs:110-162` defines the struct; `src/runtime/runtime.rs:2554` defines `impl Default for UiRuntime`. The winit `ApplicationHandler::window_event` is the per-window seam (`examples/widgets.rs:40` ignores `_id: WindowId`). The lib currently depends on no host windowing library — `WindowId` must be a freestanding newtype. The trait `ImeHostDriver` lives at `src/runtime/ime_host.rs:56-60`; the trait `AccessibilityBackend` lives at `src/core/a11y.rs:129`. These traits gain `: Send + Sync` in 04-02, so the static assert added in this plan (D-19) will only fully check once 04-02 lands. The static assert is safe to add now because the `Default` impl for `UiRuntime` is the backward-compat single-window path; once 04-02's trait bounds land, the assert flips to a guarantee.

</context>

## Task 1: Define `WindowId` newtype + `From<winit::WindowId>` conversion

The change is source-compatible: every existing call site that uses `UiRuntime::default()` continues to work; the runtime still has a sentinel `WindowId::unknown()` (0) for back-compat single-window use.

## Task 3: Add `dispatch_to_window` + `dispatch_app_event` + `AppEvent`

**Action:**

In `src/runtime/runtime.rs`, add `pub fn dispatch_to_window(&mut self, event: UiEvent) -> bool` that delegates to the existing `dispatch` method (D-10). The new method is the public seam multi-window hosts call. The existing `dispatch` method (the single-window path) remains in place for backward compatibility and is implemented as `self.dispatch_to_window(event)` (a thin inline forward).

Add `pub enum AppEvent` in a new file `src/runtime/app_event.rs` with variants `Quit`, `FocusWindow(WindowId)`, `ThemeChanged(Theme)`, `AppShortcut(String)`. Derive `Debug, Clone, PartialEq, Eq`. The `Theme` type is `rgui::Theme` — use the existing re-export path. Add `pub enum AppEventOutcome { Consumed, Ignored }` with the same derives. Both types are re-exported from `src/runtime/mod.rs` so they live at `rgui::AppEvent` and `rgui::AppEventOutcome`.

Add `pub fn dispatch_app_event(&mut self, event: AppEvent) -> AppEventOutcome` on `UiRuntime`. Behavior per variant:
- `Quit` returns `Consumed`; the host translates that to `event_loop.exit()`.
- `FocusWindow(target)` returns `Consumed` when `target == self.window_id` (this runtime's window is being focused; the host focuses the winit `Window`), `Ignored` otherwise (the lib doesn't dispatch to other windows; routing is the host's job).
- `ThemeChanged(theme)` updates the runtime's theme and returns `Consumed`.
- `AppShortcut(s)` looks up the shortcut string in a new `pub struct AppShortcuts { bindings: HashMap<String, Box<dyn Fn(&mut UiRuntime) + Send + Sync>> }` (built up via `register(name, closure)`); if a binding exists, invoke it and return `Consumed`; otherwise `Ignored`. Default `AppShortcuts::new()` returns an empty map. `UiRuntime` gains an `app_shortcuts: AppShortcuts` field initialized in `for_window`.

The `AppShortcuts` type is the host's extensibility surface for cross-window shortcuts (think `Cmd+W` to close the active window, even when focus is in a child widget). It lives in the same file as `AppEvent`.

Write 2 unit tests in `src/runtime/app_event.rs`:
1. `app_event_quit_is_consumed` — `let mut rt = UiRuntime::default(); assert!(matches!(rt.dispatch_app_event(AppEvent::Quit), AppEventOutcome::Consumed));`
2. `app_event_focus_window_only_consumed_for_self` — `assert!(matches!(rt.dispatch_app_event(AppEvent::FocusWindow(rt.window_id())), AppEventOutcome::Consumed)); assert!(matches!(rt.dispatch_app_event(AppEvent::FocusWindow(WindowId::new(99))), AppEventOutcome::Ignored));`

`UiRuntime` gets a `pub fn window_id(&self) -> WindowId { self.window_id }` accessor so the test and host can read the invariant.

**Verify:** `cargo test --lib runtime::app_event::tests` passes; `cargo doc --no-deps` shows the new types and methods.

**Files:** `src/runtime/app_event.rs` (new); `src/runtime/mod.rs` (re-exports); `src/runtime/runtime.rs` (add `dispatch_to_window`, `dispatch_app_event`, `window_id()` accessor, `app_shortcuts` field).

**Depends on:** Task 2 (needs `window_id` field on `UiRuntime`).
**Parallel:** no.

## Task 4: Add static `Send + Sync` assertion to `UiRuntime`

**Action:**

In `src/runtime/runtime.rs`, immediately after the `UiRuntime` struct definition (around line 162), add the static assertion from D-19:

```
const _: fn() = || { fn assert<T: Send + Sync>() {} assert::<UiRuntime>(); };
```

Add a one-line comment above the assertion: `// D-19: regression guard. Fails to compile if a future field makes UiRuntime !Send or !Sync.`

The assertion will compile today because the existing `UiRuntime` fields are all `Send + Sync`; the only fields that could regress are `Box<dyn ImeHostDriver>` and `Box<dyn AccessibilityBackend + ?Sized>`, neither of which yet carries the explicit `: Send + Sync` trait bound. Those bounds land in 04-02. The static assert is a forward-looking regression guard: it documents the invariant the lib wants, and if someone in the future adds a non-Send field, the build breaks before the runtime is shipped to hosts.

**Verify:** `cargo build --lib` succeeds; the assertion is visible in `cargo expand --lib runtime` output (or `cargo rustc --lib -- -Zunpretty=expanded` if using nightly); removing the trait bound on `ImeHostDriver` in a future change would make this assert fail.

**Files:** `src/runtime/runtime.rs` (add the static assert after the struct definition).

**Depends on:** Task 2 (the `UiRuntime` struct must exist in its final form).
**Parallel:** yes (single-line addition, can land alongside Task 3).

## Task 5: Migrate 5 winit examples to `WindowId` + `for_window`

**Action:**

The five winit examples to migrate are:
- `examples/basic_window.rs`
- `examples/widgets.rs`
- `examples/visual_showcase.rs`
- `examples/rml_showcase.rs`
- `examples/rml_widget_gallery.rs`

For each example:

1. Change the `ApplicationHandler::window_event` signature from `fn window_event(&mut self, event_loop: &ActiveEventLoop, _id: WindowId, event: WindowEvent)` to `fn window_event(&mut self, event_loop: &ActiveEventLoop, id: WindowId, event: WindowEvent)` (drop the underscore, capture the id).
2. In the `resumed` (or equivalent) handler, change `let runtime = UiRuntime::default();` to `let runtime = UiRuntime::for_window(self.window_id.unwrap_or(WindowId::unknown()), &ProcessContext::new());` (using the local winit `WindowId` to construct the runtime's id — `WindowId::from(self.window.as_ref().unwrap().id())`). If the example uses a single field `runtime: UiRuntime`, leave it; the per-window identity is implicit in the field.
3. Add a `window_id: Option<rgui::WindowId>` field to the example's `App` struct that captures the winit `WindowId` in `resumed` and clears it on `destroyed` / `close_requested`. The host uses this to construct new runtimes if windows are created dynamically (only `multi_window.rs` does this, but the field is harmless in single-window examples).
4. Remove the now-unused `use winit::window::WindowId;` imports if no longer used. Keep them only if the example references the winit `WindowId` for something other than the `_id` parameter (most don't).
5. Add `use rgui::WindowId;` (or fully qualify) at the top of the example to bring the new type into scope.

Do not change the render path, the event dispatch flow, or any widget construction logic. The migration is purely about adopting the new `WindowId` + `for_window` shape. The 5 examples should compile and run identically to before the migration.

**Verify:** `cargo build --examples` succeeds; `cargo run --example basic_window` (or the equivalent non-interactive test) compiles. If the project has a `cargo test --doc` step, run it.

**Files:** `examples/basic_window.rs`, `examples/widgets.rs`, `examples/visual_showcase.rs`, `examples/rml_showcase.rs`, `examples/rml_widget_gallery.rs` (all modified).

**Depends on:** Tasks 1–3 (need `WindowId`, `for_window`, `ProcessContext` stub).
**Parallel:** yes across the 5 examples (each is a separate file).

<notes>

**Relationship to 04-02:** This plan lands the `ProcessContext` as a zero-sized stub so the `for_window` signature is stable. Plan 04-02 expands `ProcessContext` to the full D-13 shape (`NodeIdAllocator` + `SharedAccessibility`) and adds the `: Send + Sync` bounds to the traits. The static assert in this plan will only fail to compile if someone adds a `!Send` field to `UiRuntime` *after* 04-02's bounds land.

**Why `AppShortcuts` is in this plan, not deferred:** The `AppEvent::AppShortcut(String)` variant is part of D-12 (AppEvent's contract). The binding storage is the smallest possible home for it; shipping the enum without the binding would make the variant unusable.

**Why `dispatch_to_window` is a forwarder:** The existing `dispatch` method is the single-window path that the lib has used since Phase 2. Renaming it would be a breaking change to the public API. The forwarder keeps the old name working while making the multi-window name the recommended one.

**Risk:** The `AppShortcuts` closure type is `Box<dyn Fn(&mut UiRuntime) + Send + Sync>`. This is fine because `UiRuntime: Send + Sync` (per the static assert) and the closures don't escape the runtime. If a host needs `'static` closures that hold non-`Send` data, that's a v1.x follow-up.

</notes>
