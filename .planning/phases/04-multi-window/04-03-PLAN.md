<objective>

Land the rendering half of multi-window: a `SharedWgpuDevice` that holds the process-wide `Adapter / Device / Queue / GpuAtlas`, a `WgpuRenderer::with_shared_device` constructor that builds a per-window renderer from a shared device, a runnable two-window example that demonstrates runtime isolation, and three integration tests that lock in WIN-02 / WIN-03 / WIN-04.

The output is a process that can open two winit windows, route events to two runtimes, and prove the runtimes are independent (different `window_id`s, disjoint `(window_id, node_id)` tuples, events on one runtime do not affect the other) — all while sharing a single GPU device and atlas.

## Task 1: Define `SharedWgpuDevice` with async constructor + atlas wrapping

**Action:**

Add a new file `src/render/wgpu/shared_device.rs`. Define:

```
use std::sync::{Arc, Mutex};

pub struct SharedWgpuDevice {
    adapter: Arc<wgpu::Adapter>,
    device: Arc<wgpu::Device>,
    queue: Arc<wgpu::Queue>,
    atlas: Arc<Mutex<GpuAtlas>>,
}

impl SharedWgpuDevice {
    pub async fn new() -> Result<Self, RendererError> {
        // Reuse the adapter/device/queue acquisition logic from
        // WgpuRenderer::request_device. The "no surface" path is new —
        // today the lib requires a surface to call request_adapter. Use
        // wgpu::Instance::request_adapter(&wgpu::RequestAdapterOptions {
        //     power_preference: wgpu::PowerPreference::default(),
        //     force_fallback_adapter: false,
        //     compatible_surface: None,  // NEW: not tied to any surface
        // }) and then request_device on the adapter.
        // ...
    }

    pub fn adapter(&self) -> &Arc<wgpu::Adapter> { &self.adapter }
    pub fn device(&self) -> &Arc<wgpu::Device> { &self.device }
    pub fn queue(&self) -> &Arc<wgpu::Queue> { &self.queue }
    pub fn atlas(&self) -> &Arc<Mutex<GpuAtlas>> { &self.atlas }
}

impl Clone for SharedWgpuDevice {
    fn clone(&self) -> Self { ... }  // all fields are Arc-wrapped; trivial.
}
```

The `new()` constructor is `async` because `wgpu::request_adapter` and `wgpu::Adapter::request_device` are async. Production hosts call it inside their async runtime; tests use `pollster::block_on(SharedWgpuDevice::new())` (matching the pattern in `examples/widgets.rs:34`).

Construct the `GpuAtlas` once in `new()`. The atlas is shared (D-07): every `WgpuRenderer` built from this `SharedWgpuDevice` reads from the same atlas, so glyphs uploaded by one window are visible to all windows. The `Arc<Mutex<GpuAtlas>>` wrapper (D-09) is the lib's choice for the v1.x; a future version can swap to `RwLock` or a lock-free structure.

In `src/render/wgpu/mod.rs`, add `pub mod shared_device;` and `pub use shared_device::SharedWgpuDevice;` so the type is reachable as `rgui::render::wgpu::SharedWgpuDevice`.

**Verify:** `cargo build --lib` succeeds; the new module is reachable; `SharedWgpuDevice::new()` returns a value (test it under `#[cfg(test)]` with `pollster::block_on` if a headless test environment exists, otherwise mark the test as `#[ignore]` and document that it requires a real GPU).

> The shared atlas is wrapped in `Arc<Mutex<GpuAtlas>>`. Per-frame bind group construction locks the mutex briefly; glyph uploads also lock the mutex. Contention is rare in practice (most frames don't upload new glyphs). Profiling can guide a future swap to `RwLock` if contention becomes a bottleneck.

## Task 4: Create `examples/multi_window.rs` (D-05)

**Action:**

Add a new file `examples/multi_window.rs` that demonstrates two winit windows sharing a `SharedWgpuDevice`, two `UiRuntime` instances, and per-window event routing.

Structure:

```
use std::collections::HashMap;
use std::sync::Arc;

use rgui::render::wgpu::{RendererOptions, SharedWgpuDevice, SurfaceRenderer};
use rgui::runtime::{FrameInput, ProcessContext, UiRuntime, WindowId};
use rgui::widgets::{button, column, text, Element};
use rgui::{Color, Point, SizeU32, Theme, UiEvent};

use winit::{
    application::ApplicationHandler,
    event::WindowEvent,
    event_loop::{ActiveEventLoop, EventLoop},
    window::{Window, WindowAttributes, WindowId as WinitWindowId},
};

struct AppWindow {
    runtime: UiRuntime,
    surface: SurfaceRenderer,  // owns the wgpu::Surface
    window: Window,
    counter: i32,
}

struct MultiWindowApp {
    shared: Option<SharedWgpuDevice>,
    ctx: ProcessContext,
    windows: HashMap<WinitWindowId, AppWindow>,
    next_window_id: u32,
}

impl ApplicationHandler for MultiWindowApp {
    fn resumed(&mut self, event_loop: &ActiveEventLoop) {
        // Lazily create the SharedWgpuDevice on the first resumed call.
        if self.shared.is_none() {
            self.shared = Some(pollster::block_on(SharedWgpuDevice::new()).expect("shared device"));
        }
        // Create two windows.
        for title in ["Window A", "Window B"] {
            let window = event_loop
                .create_window(WindowAttributes::default().with_title(title))
                .expect("window creates");
            let surface = pollster::block_on(SurfaceRenderer::with_shared_device(
                self.shared.as_ref().unwrap(),
                &window,
                RendererOptions::default(),
            )).expect("surface renderer");
            let rgui_id = WindowId::new(self.next_window_id as u64);
            self.next_window_id += 1;
            let runtime = UiRuntime::for_window(rgui_id, &self.ctx);
            self.windows.insert(window.id(), AppWindow { runtime, surface, window, counter: 0 });
        }
    }

    fn window_event(&mut self, _event_loop: &ActiveEventLoop, id: WinitWindowId, event: WindowEvent) {
        let Some(win) = self.windows.get_mut(&id) else { return; };
        // Translate winit event to UiEvent and dispatch_to_window.
        // Pointer move / button / etc. — pattern from examples/widgets.rs.
        if let WindowEvent::CloseRequested = event {
            // The host decides what to do (e.g. remove from the map).
            return;
        }
        // Render this window's frame.
        let input = FrameInput { viewport: SizeU32::new(800, 600), ..Default::default() };
        let _ = win.runtime.update(input);
        // win.surface.render(win.runtime.last_displaylist())  — verify the
        // exact wgpu API for rendering a DisplayList; the existing
        // examples/widgets.rs has the pattern.
    }
}

fn main() {
    let event_loop = EventLoop::new().expect("event loop");
    let app = MultiWindowApp {
        shared: None,
        ctx: ProcessContext::new(),
        windows: HashMap::new(),
        next_window_id: 1,
    };
    event_loop.run_app(app).expect("run");
}
```

The counter labels in each window (`text(format!("A: {}", win.counter))`, `text(format!("B: {}", win.counter))`) prove runtime isolation: a click on window A's button only mutates A's `counter` field; window B's `counter` is unchanged. The example does not need to be perfect — it needs to be runnable and demonstrate the multi-window pattern.

Use `rgui::WindowId::new(self.next_window_id as u64)` for the lib's `WindowId`, and `window.id()` (the winit `WindowId`) as the key into the host's `HashMap`. The conversion is one-way: winit → rgui via `From<winit::WindowId>` (from 04-01's `winit` feature impl).

**Verify:** `cargo build --example multi_window --features winit` succeeds. (Running the example requires a display; CI just checks the build.)

## Task 5: Write `tests/multi_window_coexistence.rs` (WIN-02)

**Action:**

Add a new integration test file `tests/multi_window_coexistence.rs` that verifies two `UiRuntime` instances can coexist in the same process. This is the WIN-02 verification.

```
use rgui::runtime::{FrameInput, ProcessContext, UiRuntime, WindowId};
use rgui::widgets::{column, text};
use rgui::Element;

#[test]
fn two_runtimes_in_one_process_have_independent_snapshots() {
    let ctx = ProcessContext::new();
    let mut a = UiRuntime::for_window(WindowId::new(1), &ctx);
    let mut b = UiRuntime::for_window(WindowId::new(2), &ctx);

    let tree_a = column().push(text("A")).into_element();
    let tree_b = column().push(text("B")).into_element();

    let input = FrameInput::default();
    let _ = a.update_with(input.clone(), tree_a);
    let _ = b.update_with(input, tree_b);

    let snap_a = a.last_output().debug_snapshot();
    let snap_b = b.last_output().debug_snapshot();

    assert_eq!(snap_a.window_id, WindowId::new(1));
    assert_eq!(snap_b.window_id, WindowId::new(2));
    assert_ne!(snap_a.display_list_len, snap_b.display_list_len);
}

#[test]
fn process_context_node_ids_are_shared_across_runtimes() {
    let ctx = ProcessContext::new();
    let mut a = UiRuntime::for_window(WindowId::new(1), &ctx);
    let mut b = UiRuntime::for_window(WindowId::new(2), &ctx);
    let tree = column().push(text("x")).into_element();
    let _ = a.update_with(FrameInput::default(), tree.clone());
    let _ = b.update_with(FrameInput::default(), tree);
    // Both runtimes consumed ids from the same global counter.
    // a's first id is 0, b's first id is 1 (or whatever the count is).
    let snap_a = a.last_output().debug_snapshot();
    let snap_b = b.last_output().debug_snapshot();
    let ids_a: Vec<u64> = snap_a.nodes.iter().map(|n| n.id).collect();
    let ids_b: Vec<u64> = snap_b.nodes.iter().map(|n| n.id).collect();
    // Disjoint id sets: the two runtimes drew from the same counter,
    // so the union is a monotonic range with no overlap.
    for id in &ids_a {
        assert!(!ids_b.contains(id), "node id {id} appears in both runtimes");
    }
}
```

The exact field names on `UiSnapshot` depend on what's in `src/core/snapshot.rs`. The test should be written to match the actual field names. The key invariant: `snap_a.window_id != snap_b.window_id`, and the node id sets are disjoint.

```
use rgui::runtime::{FrameInput, ProcessContext, UiRuntime, WindowId};
use rgui::widgets::{button, column};
use rgui::{Element, PointerButton, PointerEvent, UiEvent};

#[test]
fn pointer_event_to_a_does_not_change_b_focus() {
    let ctx = ProcessContext::new();
    let mut a = UiRuntime::for_window(WindowId::new(1), &ctx);
    let mut b = UiRuntime::for_window(WindowId::new(2), &ctx);

    let tree = column().push(button("X")).into_element();
    let input = FrameInput::default();
    let _ = a.update_with(input.clone(), tree.clone());
    let _ = b.update_with(input, tree);

    // Initially neither runtime has focus.
    assert!(a.focused_node().is_none());
    assert!(b.focused_node().is_none());

    // Dispatch a pointer click at the button in A.
    let consumed = a.dispatch_to_window(UiEvent::Pointer(PointerEvent::Button {
        button: PointerButton::Left,
        state: rgui::PointerState::Pressed,
        x: 50.0,
        y: 50.0,
    }));
    assert!(consumed, "A should consume the event");

    // A has focus; B does not.
    assert!(a.focused_node().is_some(), "A gained focus");
    assert!(b.focused_node().is_none(), "B was untouched");
}

#[test]
fn ime_event_routes_to_target_runtime_only() {
    use rgui::core::ImePreedit;
    let ctx = ProcessContext::new();
    let mut a = UiRuntime::for_window(WindowId::new(1), &ctx);
    let mut b = UiRuntime::for_window(WindowId::new(2), &ctx);

    let _ = a.update_with(FrameInput::default(), column().into_element());
    let _ = b.update_with(FrameInput::default(), column().into_element());

    let preedit = ImePreedit { text: "abc".into(), cursor_byte_range: 0..3 };
    a.dispatch_to_window(UiEvent::ImePreedit(preedit));

    // A has preedit state; B does not.
    assert!(a.active_ime().is_some());
    assert!(b.active_ime().is_none());
```

## Task 7: Write `tests/multi_window_snapshot_isolation.rs` (WIN-04)

**Action:**

Add `tests/multi_window_snapshot_isolation.rs` that verifies the snapshot's `(window_id, node_id)` tuples are unique process-wide (D-14).

```
use rgui::runtime::{FrameInput, ProcessContext, UiRuntime, WindowId};
use rgui::widgets::{column, text};
use rgui::Element;
use std::collections::HashSet;

#[test]
fn snapshots_from_two_runtimes_have_disjoint_node_ids() {
    let ctx = ProcessContext::new();
    let mut a = UiRuntime::for_window(WindowId::new(1), &ctx);
    let mut b = UiRuntime::for_window(WindowId::new(2), &ctx);

    let tree = column().push(text("hello")).into_element();
    let _ = a.update_with(FrameInput::default(), tree.clone());
    let _ = b.update_with(FrameInput::default(), tree);

    let snap_a = a.last_output().debug_snapshot();
    let snap_b = b.last_output().debug_snapshot();

    let ids_a: HashSet<(u64, u64)> = snap_a.nodes.iter().map(|n| (snap_a.window_id.raw(), n.id)).collect();
    let ids_b: HashSet<(u64, u64)> = snap_b.nodes.iter().map(|n| (snap_b.window_id.raw(), n.id)).collect();

    let intersection: usize = ids_a.intersection(&ids_b).count();
    assert_eq!(intersection, 0, "snapshots share a (window_id, node_id) tuple");
}

#[test]
fn node_id_counter_is_monotonic_across_runtimes() {
    let ctx = ProcessContext::new();
    let mut a = UiRuntime::for_window(WindowId::new(1), &ctx);
    let mut b = UiRuntime::for_window(WindowId::new(2), &ctx);

    let tree = column().push(text("x")).into_element();
    let _ = a.update_with(FrameInput::default(), tree.clone());
    let _ = b.update_with(FrameInput::default(), tree);

    // The process-global counter advanced by the total number of nodes issued.
    // For one column + one text node per runtime, the counter should be at 4.
    let counter = ctx.node_ids().current();
    assert!(counter >= 4, "expected at least 4 node ids issued, got {counter}");
}
```

<notes>

**Why `Arc<Mutex<GpuAtlas>>` (not `Arc<RwLock<GpuAtlas>>`):** `Mutex` is the conservative choice (D-09). Read-heavy workloads (per-frame bind group construction) and write-light workloads (glyph uploads) both contend on the same lock, but the critical sections are brief. `RwLock` is a v1.x follow-up if profiling shows contention.

**Why the new `SharedWgpuDevice::new` constructor is async (not blocking):** `wgpu::request_adapter` and `wgpu::request_device` are async by design. The lib doesn't ship a blocking helper; the host decides which runtime to await on. Tests use `pollster::block_on` (matching the pattern in `examples/widgets.rs:34`).

**Why `SurfaceRenderer::with_shared_device` is a separate constructor (not a method on `SurfaceRenderer::new`):** The existing `SurfaceRenderer::new` is the single-window path. Adding a `&SharedWgpuDevice` parameter would be a breaking change. The new constructor is additive and the host picks the right one.

**Why WIN-01 is not explicitly tested:** WIN-01 is "the runtime supports N windows", which is a structural property — verified by `examples/multi_window.rs` compiling and running. There is no single assertion that captures "supports N"; the test would just be "compile and don't panic". The integration tests cover the behavioral properties (WIN-02, WIN-03, WIN-04).

**Relationship to 04-01 and 04-02:** This plan depends on the `WindowId` newtype (04-01 Task 1), the `for_window` constructor (04-01 Task 2), `dispatch_to_window` (04-01 Task 3), the `ProcessContext` (04-02 Task 3), and the `NodeIdAllocator` (04-02 Task 1). All three plans together satisfy WIN-01..04.

**Risk:** The wgpu 29 + winit 0.30 surface model requires `wgpu::Surface<'static>`, which means the `WgpuRenderer::with_shared_device` signature needs careful lifetime plumbing. The plan acknowledges this in D-08's "Claude's Discretion" area. If the borrow checker complains, the fix is to add an explicit `unsafe impl Send/Sync` on a wrapper (documented and scoped to the surface), or to thread the surface through a `Pin<Box<dyn FnMut>>` callback. The integration tests don't construct real wgpu surfaces (they only test the runtime-level isolation), so the GPU-side lifetime issue doesn't block test progress.

</notes>
