# Plan 03-02: CJK + Arabic shaping in glyphon integration

## Objective

Add integration tests proving that the `glyphon` 0.11 + `cosmic-text` shaping
path renders CJK (Japanese kanji) and Arabic (including contextual letter
forms and bidi) without errors on the wgpu headless backend. Ship a CI
font-install script and a `CONTRIBUTING.md` "System fonts" section. Tests
that require a missing font skip with a `tracing::warn!` (so contributors on
hosts without Noto CJK don't get a hard failure); CI installs fonts first
via the script.

## Context

Phase 3 `03-CONTEXT.md` Decisions 2 and 3 lock in:

- **System fonts (no bundled fonts)**: tests assume `fonts-noto-cjk` and
  `fonts-noto` are installed; CI installs via `scripts/ci-install-fonts.sh`.
  `RGUI_REQUIRE_FONTS=1` opt-in env var converts the skip-with-warning path
  to a hard failure (for CI strict mode).
- **Arabic is the v1 RTL reference**: test 3 sub-cases — isolated,
  contextual, bidi.
- `Shaping::Advanced` is already the default in
  `src/render/wgpu/glyphon_text.rs:183`; the test pins it explicitly so a
  future refactor to `Shaping::Basic` would fail the test.

The existing test suite (`tests/visual_goldens.rs`, `tests/widgets_native.rs`)
only exercises Latin. No prior test pins Arabic or CJK behavior.

6. **Test 3**: `#[test] fn arabic_contextual_shaping_produces_joined_glyphs()` — skip pattern for `:lang=ar`. 7. **Test 4**: `#[test] fn arabic_latin_bidi_renders_in_correct_order()` — skip pattern for `:lang=ar`. Call `shape_string("Hello بسم")` and assert: (a) no glyph has NaN x_advance, (b) glyphs are in increasing x position along the baseline (cumulative x_offset is monotonically non-decreasing), (c) total width > 0.

## Notes

- Test #3 (contextual shaping) is the strongest signal that real shaping happened. If the project's `cosmic-text` version ever falls back to `Shaping::Basic`, the test will fail because `Basic` does not do contextual substitution.
- The skip-with-warning pattern is `if !is_noto_X_installed() && std::env::var("RGUI_REQUIRE_FONTS").is_err() { tracing::warn!(...); return; }`. This is a no-op success path; no `#[ignore]`.
- The `fc-list` check is the cheapest font presence check. If a host uses a different font registration system (e.g. macOS), the helper returns `true` and the test relies on the actual `shape_string` call to either succeed or fail with a meaningful error.

## Threat model

- **Threat**: A malicious or corrupted font file in the system could cause cosmic-text to crash.
- **Mitigation**: cosmic-text handles bad font data gracefully (we trust upstream). The tests shape known strings; if a font is corrupted, the test fails with a clear error.
- **Threat**: CI hosts may not have `fc-list` available.
- **Mitigation**: The `is_noto_*_installed` helpers return `true` if `fc-list` is missing; the test relies on the actual shape call.
- **Severity**: low. No auth/network; the worst case is a flaky test, which the skip path handles.
