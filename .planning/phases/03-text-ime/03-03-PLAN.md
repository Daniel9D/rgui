# Plan 03-03: TextCacheStats observability and clear_text_cache public API

## Objective

Expose `TextCacheStats` to application code in three places
(`UiRuntime::text_cache_stats()`, `UiSnapshot.text_cache`,
`RendererStats.text_cache`) and add a public `clear_text_cache()` method
on `UiRuntime` plus the symmetric `pub fn text_metrics_cache_stats()` for
the heuristic path. Closes TEXT-03 (cache observability) and TEXT-04
(public clear API).

## Context

`TextCacheStats` already exists on `TextSystem` (in
`src/text_engine/system.rs:49-56`) with `cache_stats()` returning hit /
miss / entry counts. The struct is `#[derive(Clone, Copy, Debug, Default,
PartialEq, Eq)]`. The issue is reachability: an app wanting to log cache
hit rate has to call into `TextSystem` directly, which is not part of the
public surface. The clearing story is also split: the heuristic
`clear_metrics_cache()` is a free function in `runtime/text_metrics.rs`
but the shape/layout cache on `TextSystem` has no public clear at all.

This plan:

1. Adds `TextSystem::clear_caches() -> (usize, usize)` (low-level
   primitive).
2. Adds `UiRuntime::text_cache_stats() -> TextCacheStats` and
   `UiRuntime::clear_text_cache() -> (usize, usize)` (public API).
3. Adds `pub fn text_metrics_cache_stats()` for the heuristic path
   (already exists per `text_metrics.rs:97` — verify and re-export if
   needed).
4. Adds `text_cache: TextCacheStats` to `UiSnapshot` (so debug JSON
   includes it) and to `RendererStats` (so the live render-stats hook
   includes it).

## Notes

- Total tests added by this plan: 5 (2 unit + 3 integration across the 3 new test files; one test in #2 covers `text_metrics_cache_stats`, one in #3 covers snapshot, one in #4 covers RendererStats, plus the 2 in #1).
- The new `clear_text_cache()` is opt-in: no implicit eviction. An app that never calls it sees unbounded growth (the same as today; LRU is a v1.x follow-up).
- The `RendererStats` field is a `Copy` type; populating it from the bridge is just a struct copy.

## Threat model

- **Threat**: A malicious `TextSystem` impl could lie about hit/miss counters to mask a bug.
- **Mitigation**: `TextSystem` is internal; the public API only exposes the read-only `TextCacheStats`. No code path takes user input and feeds it to the cache counters.
- **Threat**: `clear_text_cache` could be called mid-render, causing a use-after-clear panic.
- **Mitigation**: `clear_text_cache` requires `&mut self` on `UiRuntime`; the runtime does not borrow `text_system` during a render. If a future refactor borrows it, the borrow checker catches the conflict.
- **Severity**: low. Stats are observability, not security.
