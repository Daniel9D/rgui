# Plan 02-04: IME composition events for text input

**Phase:** 2 (Event & Input Hardening)
**Plan:** 04 of 04
**Type:** task
**Goal:** Route `ImePreedit` / `ImeCommit` events to the focused
`Input` element when `ime_enabled: true`. Display the preedit
text underlined; commit replaces the preedit with the committed
text.

## Context

`UiEvent::ImePreedit(ImePreedit)` and `UiEvent::ImeCommit(String)`
exist in `src/core/event.rs`. The dispatch in `src/runtime/events.rs`
discards them — they don't reach the focused `Input` element. Users
who type in CJK languages (Japanese, Chinese, Korean) can't use
the library because their IME preedit text doesn't appear.

This plan adds:
1. `InputSpec::ime_enabled: bool` (default `false`).
2. `InputState` (the runtime state for an Input) gets `preedit: String` + `preedit_cursor: Option<(usize, usize)>`.
3. Dispatch routes `ImePreedit` / `ImeCommit` to the focused Input.
4. Paint shows `value` + `preedit` (underlined) + cursor.

## Scope

**In scope:**
- `InputSpec::ime_enabled: bool`
- `InputState::preedit: String` + `preedit_cursor`
- Dispatch: on `ImePreedit(text, range)` and `ime_enabled`, set `state.preedit = text` and `state.preedit_cursor = range`
- Dispatch: on `ImeCommit(text)` and `ime_enabled`, append to `state.value` at the cursor and clear `preedit`
- Paint: the Input element shows `preedit` underlined (via the existing text style's `underline` field)
- 3 unit tests + 2 integration tests

**Out of scope:**
- South-East Asian complex-script state machine (v1.x; v1 covers CJK preedit-then-commit)
- Per-character preedit composition (Hindi, Thai, Khmer — deferred)
- IME panel UI (the host OS draws it; v1 only handles the events)

## Tasks

1. **TDD-02-04-01**: Unit test — `InputState::apply_preedit(text, range)` sets `preedit = text` and `preedit_cursor = range`.
2. **TDD-02-04-02**: Unit test — `InputState::apply_commit(text)` appends `text` to `value` at the cursor and clears `preedit`.
3. **TDD-02-04-03**: Unit test — `InputState::cancel_preedit()` clears `preedit` and `preedit_cursor` (called on focus loss).
4. **TDD-02-04-04**: Add `InputSpec::ime_enabled: bool` (default `false`). All `InputSpec { ... }` constructions in the codebase get the new field via `..Default::default()`. The `input()` builder does not set it (default `false`).
5. **TDD-02-04-05**: Add `InputState::preedit: String` + `preedit_cursor: Option<(usize, usize)>` (the latter is the byte range in `value` that the preedit replaces; v1 stores it for future use, currently unused in paint).
6. **TDD-02-04-06**: Implement the dispatch in `src/runtime/events.rs`:
   - On `ImePreedit { text, cursor_byte_range }`: if the focused node is an `Input` with `ime_enabled`, call `InputState::apply_preedit`.
   - On `ImeCommit(text)`: if the focused node is an `Input` with `ime_enabled`, call `InputState::apply_commit`.
7. **TDD-02-04-07**: Update the focus-loss path: when focus moves away from an Input with an active preedit, call `InputState::cancel_preedit`. (This is the same code path that already runs on focus loss; just add the preedit-clear call.)
8. **TDD-02-04-08**: Update the paint path for the Input element: render `value + preedit` (where `preedit` is underlined via `TextStyle::underline` or a new `Paint::Underline`). The cursor is drawn at the end of `value` or at the end of `preedit`, whichever is appropriate (v1: end of `value` when no preedit; end of `preedit` when there is one).
9. **TDD-02-04-09**: Integration test — `ime_preedit_routes_to_focused_input`: focus an `Input` with `ime_enabled: true`; dispatch `ImePreedit { text: "あ", ... }`; assert `InputState.preedit == "あ"`.
10. **TDD-02-04-10**: Integration test — `ime_commit_replaces_preedit_with_committed_text`: same setup; dispatch `ImePreedit { text: "あ", ... }`; then dispatch `ImeCommit("あ")`; assert `InputState.value == "あ"` and `InputState.preedit.is_empty()`.

## Risks

- **The existing `InputState` is in `src/runtime/state.rs`; the existing key-set test (TDD-02-04-04 from a prior plan) may need updates.** This is a `Default` change, so all default-constructed InputStates get `preedit: String::new()`, which is the right initial state.
- **Underlining the preedit may require a new `Paint::Underline` variant.** The existing paint path supports `Paint::Solid` and `Paint::LinearGradient`; a new `Paint::Underline` is the cleanest way. The painter for the Input element uses the new variant when `preedit` is non-empty.
- **IME is host-dependent.** The host (winit, browser) is responsible for sending `ImePreedit` / `ImeCommit` events. v1 tests simulate the events directly; the actual host integration is a v1.x task (or stays as a winit-specific module).
- **The preedit display has no width measurement for v1.** A preedit string of 10 CJK characters may overflow the input box. v1 clips at the input's right edge; v1.x adds proper measurement and scroll.
