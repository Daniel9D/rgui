# Plan 02-02: Shortcut suppression inside text inputs

**Phase:** 2 (Event & Input Hardening)
**Plan:** 02 of 04
**Type:** task
**Goal:** When the focused node is a text input, suppress
shortcuts that don't include a `Cmd`/`Ctrl`/`Alt` modifier so
the user can type letters / digits / punctuation without firing
global shortcuts.

## Context

`ShortcutRegistry::resolve` (in `src/core/event.rs`) currently
takes `(chord, focused)` and walks the registered shortcuts in
priority order. It does *not* check whether the focused node is a
text input. Result: a user typing `a` in an `Input` element with a
registered global shortcut for `a` (e.g. an "approve" action bound
to `a`) sees both the letter typed and the shortcut fire.

This plan adds a `focused_is_text_input: bool` argument and the
"modifier-only shortcuts always fire" rule.

## Scope

**In scope:**
- `ShortcutRegistry::resolve` signature change: add `focused_is_text_input: bool`
- Suppression rule: when `focused_is_text_input` is true, skip shortcuts that don't have a `Cmd`/`Ctrl`/`Alt` modifier
- All call sites of `resolve` updated (runtime dispatch, tests, examples)
- 4 unit tests + 2 integration tests

**Out of scope:**
- Shortcut re-binding UI (v1.x)
- Custom chord parsing (v1 uses simple string equality)
- Cross-platform modifier normalization (`Cmd` on macOS, `Ctrl` on Win/Linux — already handled by the host; v1 assumes the host produces `Cmd` on macOS and `Ctrl` elsewhere)

## Tasks

1. **TDD-02-02-01**: Unit test — `resolve` with a plain-letter chord (e.g. `"a"`) and `focused_is_text_input: true` returns `None` (suppressed).
2. **TDD-02-02-02**: Unit test — `resolve` with a modifier-prefixed chord (e.g. `"Cmd+a"`) and `focused_is_text_input: true` returns the action (modifiers always fire).
3. **TDD-02-02-03**: Unit test — `resolve` with `focused_is_text_input: false` returns the action for any chord (existing behavior).
4. **TDD-02-02-04**: Unit test — `resolve` with a digit / punctuation chord (`"1"`, `"?"`, `"Enter"`) and `focused_is_text_input: true` returns `None` (Enter is *not* a modifier-prefixed shortcut, so it's suppressed too).
5. **TDD-02-02-05**: Add a `is_modifier_chord(&str) -> bool` helper in `src/core/event.rs` that returns `true` if the chord contains `Cmd+`, `Ctrl+`, or `Alt+`. Document the rule: modifier-prefixed shortcuts always fire; bare-letter/digit/punctuation/function-key shortcuts are suppressed inside text inputs.
6. **TDD-02-02-06**: Update `ShortcutRegistry::resolve` to take `focused_is_text_input: bool` and apply the suppression rule.
7. **TDD-02-02-07**: Update all call sites of `resolve`. The runtime dispatch in `src/runtime/events.rs` reads the focused node's `widget_spec`; if it's an `Input` / `Textarea` / `Select`, pass `focused_is_text_input: true` to `resolve`. Otherwise pass `false`. The default for the test helper is `false` to preserve existing behavior.
8. **TDD-02-02-08**: Integration test — `text_input_suppresses_plain_letter_shortcut`: register a global shortcut `"a" -> "approve"`; focus an Input; dispatch `KeyDown("a")`; assert no command was emitted.
9. **TDD-02-02-09**: Integration test — `cmd_a_fires_in_text_input`: register a global shortcut `"Cmd+a" -> "select_all"`; focus an Input; dispatch `KeyDown("Cmd+a")`; assert the command was emitted.

## Files touched

- `src/core/event.rs` (update `ShortcutRegistry::resolve` + add `is_modifier_chord`)
- `src/runtime/events.rs` (pass `focused_is_text_input` to `resolve`)
- `tests/event_input_hardening.rs` (add 2 integration tests)

## Verification

- `cargo test --lib shortcut` passes all 4 unit tests
- `cargo test --features rml,bitmap-text-fallback --test event_input_hardening` passes 2 new integration tests (in addition to the 2 from 02-01, total 4)
- `cargo test --features rml,bitmap-text-fallback` has no regressions (the existing shortcut tests in `tests/shortcut_resolution.rs` must still pass with the new signature — update them to pass `focused_is_text_input: false`)

## Risks

- **Signature change is breaking.** All call sites must be updated. The change is small (one argument) but the compiler will catch every site.
- **The `is_modifier_chord` rule is heuristic.** A shortcut `"Cmd+Shift+a"` passes (contains `Cmd+`); a shortcut `"a+1"` doesn't. This is fine for v1 — the chord format is the simple `Modifier+Key` form.
- **Existing test fixtures that use the old signature must be updated.** The test suite has multiple `resolve` call sites; all of them need the new `false` argument. This is a mechanical change.

## Handoff

After 02-02, Plan 02-03 (wheel 2D) is independent. Plan 02-04 (IME) reads `InputSpec::ime_enabled` (new field in 02-04) and routes `ImePreedit` / `ImeCommit` events to the focused Input.
