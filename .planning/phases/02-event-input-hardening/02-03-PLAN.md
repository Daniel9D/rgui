# Plan 02-03: Wheel 2D + nested scroll containers

**Phase:** 2 (Event & Input Hardening)
**Plan:** 03 of 04
**Type:** task
**Goal:** Make `WheelEvent::delta` work in both axes. Route
horizontal wheel/trackpad deltas to scroll containers that accept
horizontal scroll. Nested scroll containers consume the matching
axis and bubble the other.

## Context

`WheelEvent { delta: Vec2, ... }` already carries a 2D delta, but
the dispatch in `src/runtime/events.rs` only reads `delta.y`.
Trackpad pans that produce `delta.x ≠ 0` are silently dropped.
A horizontal scroll container can't be scrolled at all.

The Phase 2 fix:
1. The hit-test already returns the *deepest* `ScrollArea` under the pointer. Phase 2 makes that hit return *two* targets: the deepest scroll area for vertical, and the deepest for horizontal (which may be the same node, or different for nested scrolls).
2. The dispatch reads `delta.y` for vertical-target and `delta.x` for horizontal-target.
3. If a target can't scroll further on its axis, the delta bubbles to the parent.

## Scope

**In scope:**
- `PrimitiveKind::ScrollArea` gets `scroll_x: bool` + `scroll_y: bool` flags (default `true, true` for the `scroll_area()` builder; explicit values via `Element::scroll_x(true).scroll_y(false)` etc. — or a simpler `overflow(Overflow::Scroll)` and `overflow_x` / `overflow_y` setters)
- `HitTestEntry` gains an `axis` field (or a separate `wheel_horizontal_target` field) so dispatch can route each axis independently
- Dispatch: on `Wheel`, look up the two targets (vertical + horizontal); apply delta.y to vertical, delta.x to horizontal; clamp + bubble
- 4 unit tests + 3 integration tests

**Out of scope:**
- Momentum scrolling (v1.x; v1 is one-shot per wheel event)
- Smooth scrolling animation (v1 is instant)
- Inertial trackpad pan (v1.x; v1 applies each wheel event discretely)

## Risks

- **The hit-test tree currently returns a single entry per node.** Adding per-axis targets means either: (a) the hit-test returns two entries (one per axis), or (b) the wheel dispatch does its own per-axis hit-test. (b) is simpler — the wheel dispatch walks the tree from the pointer down, returning the deepest vertical-scroll and deepest horizontal-scroll separately.
- **The existing `Overflow::Scroll` setting implies both axes.** A user who previously had `Element::overflow(Overflow::Scroll)` will get a 2-axis scroll after this change. This is a behavior change but a strict improvement (previously horizontal wheel was dropped).
- **Nested scroll containers can be subtle.** A user expects the inner scroll to consume the wheel first; the outer only scrolls when the inner is at its bound. The bubble logic in TDD-02-03-03 handles this.
