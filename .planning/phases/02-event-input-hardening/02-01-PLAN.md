# Plan 02-01: Focus traversal — Tab / Shift+Tab / focus traps

**Phase:** 2 (Event & Input Hardening)
**Plan:** 01 of 04
**Type:** task
**Goal:** Add Tab / Shift+Tab traversal to `FocusManager`, plus
modal `trap_focus` so Tab loops inside a modal.

## Context

`FocusManager` (in `src/core/event.rs`) currently only stores a
single `Option<NodeId>` and supports `request_focus` + `clear` +
`focused`. There is no Tab traversal. Pressing Tab in a form does
nothing; the browser / winit captures the Tab for its own focus
cycle.

This plan adds the four pieces Phase 2 needs from the focus side:
1. `is_focusable(node) -> bool` — the predicate for "this widget can take focus".
2. `tab_next` / `tab_prev` — DOM-order traversal with wrap-around.
3. `ModalSpec::trap_focus: bool` — restricts Tab to the modal's subtree.
4. The dispatch path wires `KeyDown(Tab)` to `tab_next` (and Shift+Tab to `tab_prev`) and calls `prevent_default()` on the event so the host doesn't double-handle it.

## Scope

**In scope:**
- `FocusManager::is_focusable(&UiNode) -> bool`
- `FocusManager::tab_next(&mut self, tree: &UiTree) -> Option<NodeId>`
- `FocusManager::tab_prev(&mut self, tree: &UiTree) -> Option<NodeId>`
- `ModalSpec::trap_focus: bool` (default false)
- `KeyDown(Tab)` dispatch → `tab_next` + `prevent_default`
- `KeyDown(Shift+Tab)` dispatch → `tab_prev` + `prevent_default`
- 5 unit tests in `src/core/event.rs::tests` (focus module)
- 2 integration tests in `tests/event_input_hardening.rs` (form with Tab cycles, modal with trap loops)

**Out of scope:**
- Custom `tabindex` (v1.x; users use `request_focus` directly)
- Focus ring paint (OS / browser draws it; v1.x adds a custom ring)
- Keyboard event routing for shortcuts (Plan 02-02)
- Wheel / IME (Plans 02-03 / 02-04)

## Tasks

1. **TDD-02-01-01**: Unit test — `is_focusable` returns `true` for Button, Input, Checkbox, Radio, Select, Textarea, Switch, Slider, Link, Tabs(active), MenuItem; `false` for everything else (Row, Column, Text, Divider, Icon, Image, Badge, Card, Alert, ProgressBar, Spinner, Avatar, Popover, Tooltip, Modal itself).
2. **TDD-02-01-02**: Unit test — `tab_next` from `None` returns the first focusable in DOM order.
3. **TDD-02-01-03**: Unit test — `tab_next` from the last focusable wraps to the first.
4. **TDD-02-01-04**: Unit test — `tab_prev` from the first wraps to the last.
5. **TDD-02-01-05**: Unit test — `tab_next` on a tree where the focused node has been unmounted returns the first focusable (no panic).
6. **TDD-02-01-06**: Add `ModalSpec::trap_focus: bool` to `src/widgets/spec.rs` (default false); rebuild all `ModalSpec { .. }` constructions site-wide (use the existing `..Default::default()` pattern + 1 new field).
7. **TDD-02-01-07**: Implement `FocusManager::tab_next` and `tab_prev` in `src/core/event.rs`. The algorithm: collect all focusable `NodeId`s in DOM order; find the current focused index; return the next/prev with wrap; if a modal with `trap_focus: true` is in the ancestor chain, restrict the candidate list to that subtree.
8. **TDD-02-01-08**: Wire the dispatch in `src/runtime/events.rs`: on `KeyDown(Tab)` (with no shift), call `tab_next` + `prevent_default`; on `KeyDown(Shift+Tab)`, call `tab_prev` + `prevent_default`. (The dispatch already supports modifier flags on `KeyEvent.modifiers`.)
9. **TDD-02-01-09**: Integration test — `form_with_tab_cycles_through_focusable_widgets`: build a column with 5 buttons + 1 input, dispatch Tab 6 times, assert the focus visits each in DOM order; one more Tab wraps to the first.
10. **TDD-02-01-10**: Integration test — `modal_with_trap_focus_loops_inside`: build a tree with a button outside a modal, a button inside, and the modal with `trap_focus: true`. Focus the inside button. Dispatch Tab. Assert focus stays inside the modal (does not move to the outside button).

## Risks

- **DOM order must be stable across reconciliation.** The `Reconciler::diff` (Phase 1) is positional, so DOM order is preserved when no nodes are added/removed in the middle. The test that handles "unmounted focused node" (TDD-02-01-05) covers the edge case.
- **Modal subtree restriction needs ancestor walk.** A node's ancestors are O(depth) via `UiTree::ancestor_ids` (Phase 1 introduced this). For a typical modal with depth 5, the check is O(5) per Tab.
- **The existing `ModalSpec` is `#[non_exhaustive]`.** Adding a field is non-breaking for outside callers; inside the crate, all `ModalSpec { ... }` constructions must add the new field. The `default()` impl already derives `Default`, so most call sites can use `..Default::default()`.
