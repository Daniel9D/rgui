# Plan 01-01: `Reconciler::diff` between prior and new `Element`

**Phase:** 1 (Incremental Reconciliation)
**Plan:** 01 of 04
**Type:** task
**Goal:** Implement the structural diff between a prior `Element` root and a new `Element` root; produce a `ReconcileOutput` with the per-frame `DirtyFlags` and the list of nodes mounted / unmounted / patched.

## Context

Today the runtime builds a fresh `UiTree` from the new `Element`
on every `update()` (see `src/runtime/runtime.rs:2150+`). The
`Reconciler` struct in `src/runtime/reconcile.rs` is a skeleton
that emits `ReconcileOutput` but doesn't actually diff. This plan
wires the diff.

## Scope

**In scope:**
- `Reconciler::diff(prior_root: &Element, new_root: &Element) -> ReconcileOutput`
- Structural diff: spec hash, children position, mount / unmount / patch decisions
- Stable `NodeId` allocation via `IdAllocator` (so re-used ids survive)
- `WidgetSpec` Hash derive on every `*Spec` variant
- `ReconcileOutput` carries `mounted: Vec<NodeId>`, `unmounted: Vec<NodeId>`, `patched: Vec<NodeId>`, `dirty: DirtyFlags`

**Out of scope:**
- Layout / paint — that's plan 01-02
- Pointer-capture release on unmount — plan 01-03
- Spec-hash mismatch → re-mount — plan 01-04

## Tasks

1. **TDD-01-01-01**: Add `Hash` derive to every `*Spec` struct in `src/widgets/spec.rs`. Verify `cargo build` is clean (no new derive-bound failures).
2. **TDD-01-01-02**: Add a unit test that exercises the diff on a 3-node tree where the new tree is identical: expect zero `mounted` + zero `unmounted` + zero `patched`.
3. **TDD-01-01-03**: Add a unit test where one widget's `label` changes: expect the parent + ancestor `LAYOUT | PAINT | STYLE` flags and the changed node in `patched`.
4. **TDD-01-01-04**: Add a unit test where one child is added at the end: expect the new node in `mounted` and `LAYOUT | STRUCTURE | PAINT` for the parent.
5. **TDD-01-01-05**: Add a unit test where one child is removed: expect the node in `unmounted` and the parent with `LAYOUT | STRUCTURE | PAINT`.
6. **TDD-01-01-06**: Implement `Reconciler::diff` recursively. The diff walks children positionally; spec hash determines patch vs mount; struct membership determines unmount.
7. **TDD-01-01-07**: Add a unit test for spec-hash mismatch (different spec kinds at the same position): expect the old node in `unmounted`, the new node in `mounted`, both with `LAYOUT | STRUCTURE | PAINT`.
8. **TDD-01-01-08**: Add a `Reconciler::stats() -> ReconcileStats` accessor returning a snapshot of `mounted.len()`, `unmounted.len()`, `patched.len()`. This is the observability hook for DIAG-01.

## Risks

- **Risk:** Spec hash collisions cause incorrect "unchanged" decisions. **Mitigation:** `Hash` is a u64; collision probability is `~n²/2^65` for the spec sizes we have. Accept for v1. Add a release-mode assertion that compares structurally for at least one tree on a smoke test.
- **Risk:** `Hash` derive on every `*Spec` causes compile-time bloat. **Mitigation:** All fields are small primitive types or `Option<T>` / `Vec<T>`; the derive is mechanical and Rust handles it in O(n) per derive. No bloat expected.
- **Risk:** Stable id allocation across rebuilds breaks the `IdAllocator` invariant. **Mitigation:** `IdAllocator` is already designed for this — see its `next_id: &mut u64` API. The reconciler drives the allocator by `new` order.

## Handoff

After 01-01 ships, 01-02 (layout incremental) consumes `mounted` + `unmounted` + `dirty` to decide what to re-layout. 01-03 (capture release) consumes `unmounted` to release captures. 01-04 (spec-hash re-mount) uses the same diff but focuses on the "different spec kind" case.
