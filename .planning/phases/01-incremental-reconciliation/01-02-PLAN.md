# Plan 01-02: Dirty-region tracking on `LayoutBox`; taffy partial re-layout

**Phase:** 1 (Incremental Reconciliation)
**Plan:** 02 of 04
**Type:** task
**Goal:** Wire the `ReconcileOutput` from 01-01 into a `LayoutCache` that runs `taffy::compute_layout` over only the dirty subtree, not the full tree.

## Context

After plan 01-01, the runtime knows which nodes were mounted,
unmounted, and patched. The `LayoutCache` in `src/runtime/state.rs`
holds the previous `LayoutBox` per node. The reconciliation
output drives the cache: dirty nodes are recomputed; clean
nodes are reused.

The first-phase cost target is "less than full re-layout", not
"no re-layout at all". A node in the dirty set has its
subtree re-laid-out; sibling subtrees that did not change are
left alone.

## Scope

**In scope:**
- `LayoutCache { boxes: HashMap<NodeId, LayoutBox>, dirty: HashSet<NodeId> }`
- `LayoutCache::mark_dirty(node: NodeId)` — recursive (a dirty parent dirties its subtree)
- `LayoutCache::recompute(&mut self, tree: &UiTree, taffy: &mut TaffyTree)` — runs `taffy::compute_layout` over the dirty subtree, mapping taffy nodes back to `UiNode`s
- `LayoutCache::get(node: NodeId) -> Option<&LayoutBox>` — borrow accessor for the paint path
- Wire `LayoutCache` into the runtime `update()` loop: after reconciliation, mark dirty; before paint, recompute

**Out of scope:**
- Per-node cached layout with multi-resolution support (v1.x follow-up; Phase 1 just runs taffy over the dirty subtree, no memoization of intermediate results)
- The hit-test tree build (lives in `runtime/portal_pass.rs`; rebuilt every frame; not changed in this phase)

## Tasks

1. **TDD-01-02-01**: Add a unit test that creates a 3-node tree (root → 2 leaves), marks only one leaf dirty, calls `recompute`, and asserts that the other leaf's `LayoutBox` is unchanged.
2. **TDD-01-02-02**: Add a unit test that marks the root dirty, calls `recompute`, and asserts all descendants' `LayoutBox` are recomputed.
3. **TDD-01-02-03**: Add a unit test for `mark_dirty` propagation: marking a deep node dirty also marks its ancestors dirty (so the paint path can walk from the root down).
4. **TDD-01-02-04**: Implement `LayoutCache` with the above API. The `recompute` method walks the dirty set in tree order (parent before children) so a dirty parent's subtree is laid out as a unit.
5. **TDD-01-02-05**: Add a `LayoutCache::clear() -> ()` for use at the start of each `update()` after `reconcile.diff` returns its mounted / unmounted / patched lists. The clear removes entries for unmounted nodes; `recompute` adds entries for mounted + patched + style-changed.
6. **TDD-01-02-06**: Wire `LayoutCache` into `runtime::update`:
   - After reconciliation, mark `mounted` + `patched` as dirty
   - Before paint, call `recompute`
   - The paint path reads `LayoutCache::get(node_id)` to get the rect
7. **TDD-01-02-07**: Add a benchmark test that builds a 50-widget tree, lays it out, mutates one widget's style, calls `update` again, and asserts the second layout is < 50% of the first. This becomes the canonical performance regression test for the phase.
8. **TDD-01-02-08**: Add a debug API: `LayoutCache::stats() -> LayoutCacheStats { entries, dirty }` for the snapshot.

## Verification

- `cargo test --lib layout_cache` passes all 7 unit tests
- `cargo test --features rml,bitmap-text-fallback --test visual_goldens` still passes (no paint changes)
- The benchmark test asserts a measurable speedup on a 50-widget tree
- The smoke integration test (10 consecutive `update()` calls with a stable tree) is < 2ms per frame on the dev machine

## Risks

- **Risk:** Taffy's `compute_layout` doesn't support per-subtree recomputation; we may have to re-run the whole tree. **Mitigation:** Phase 1 benchmarks first; if taffy can't partial-recompute, fall back to "recompute from the highest dirty ancestor" which is a strict subset of the full tree. Document the trade-off.
- **Risk:** Per-node cache invalidation on style change is too aggressive. **Mitigation:** Style-change detection in `Reconciler::diff` flags the node; the cache drops the node's entry. Style changes propagate upward so the parent's layout is also recomputed. Document that v1 doesn't support *layout-level* caching; only *node-level*.
- **Risk:** Wiring into `runtime::update` introduces a perf regression in the common case (no reconciliation yet). **Mitigation:** The diff returns "no changes" for an identical tree, so `mark_dirty` adds nothing; `recompute` does nothing; the paint path reads the cache (which is still the same as the prior frame). No regression in the common case.
